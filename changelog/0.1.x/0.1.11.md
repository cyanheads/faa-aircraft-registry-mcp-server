# 0.1.11 — 2026-10-16

## Added

- **`manufacturerModelCode`** filters registrations by an exact FAA reference code and appears in search summaries; discover codes with `faa_search_aircraft_types` before looking up registrations. [#12](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/12)
- **`weightClassLabel`** decodes maximum gross takeoff weight ranges alongside the raw `weightClass`; unknown classes retain their raw value without a label. [#14](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/14)

## Changed

- **Aircraft-code descriptions** consistently advertise accepted 6–7-character codes. [#13](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/13)
- **Installation guidance** identifies existing npm mirror CLI and Node MCPB limitations, with source, Docker, Bun, and hosted alternatives. [#17](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/17), [#18](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/18)
- **Framework development guidance** synchronized for DataCanvas, validation errors, telemetry, field testing, packaging, security review, and release safeguards.

## Fixed

- **Numeric registration statuses** 1–29 now match the FAA data dictionary across lookup, status, search, and resource responses. [#9](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/9)
- **Exact search filters** reject malformed state, Mode S, aircraft type, and category values with validation reasons and recovery guidance; blank filters remain unset and valid absent values return empty pages. [#10](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/10)
- **Archive preflight** rejects missing required files and incomplete or unexpected numbered MASTER parts before changing registry tables; complete split and legacy archives remain supported. [#11](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/11)
