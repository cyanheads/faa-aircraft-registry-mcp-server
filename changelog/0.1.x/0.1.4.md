# 0.1.4 — 2026-07-15

## Added

- **`faa_search_registrations` / `faa_search_aircraft_types`** — `offset` input and `totalCount`/`nextOffset` enrichment fields for paging through capped result sets ([#4](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/4)).

## Changed

- **`faa_search_registrations` / `faa_search_aircraft_types`** — `truncated` now means "more results remain beyond this page" instead of "the result set was capped." Identical for every existing `offset=0` caller; only pagination walkers observe the new meaning ([#4](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/4)).
- **Docs** — `search-registrations.tool.ts` and `docs/design.md` corrected from "bundled registry"/"bundled on disk" to "local registry index"/"indexed on disk," matching the README's existing "not bundled" framing ([#2](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/2)).
- **Framework** — `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.10.14`; re-synced 12 agent skills and 4 devcheck scripts to match.
- **`bunfig.toml`** — added a supply-chain guard: `install.minimumReleaseAge` blocks packages published under 3 days old (first-party `@cyanheads/mcp-ts-core` excluded), and `install.security.scanner` wires in `@socketsecurity/bun-security-scanner`.

## Security

- **`faa_search_registrations`** — `makeModel` and `ownerName` free-text search is now column-scoped (`make`/`model` only; `owner_name`/`other_names` only) instead of matching every indexed FTS column. A `makeModel` query previously also matched `city` and `owner_name`, letting search probe fields the owner-PII redaction gate is meant to withhold; a search term that escapes to an empty FTS clause now returns zero results instead of silently matching every row ([#3](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/3)).
