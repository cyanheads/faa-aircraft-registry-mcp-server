# 0.1.7 — 2026-07-16

## Fixed

- **Empty-but-ready mirror** — `assertReady()` now also checks `mirror.store.count()`, rejecting an empty index with `ServiceUnavailable` (`mirror_empty`) instead of letting `faa_lookup_registration`, `faa_search_registrations`, `faa_get_registration_status`, and the aircraft-type tools return empty with `isSuccess: true` after an interrupted rebuild wipes the primary table before reloading it; `mirror:verify` now exits 1 on a ready-but-empty index instead of reporting healthy. The durable atomic-rebuild fix belongs upstream in the framework MirrorService, tracked in [cyanheads/mcp-ts-core#286](https://github.com/cyanheads/mcp-ts-core/issues/286) ([#7](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/7)).
- **Mirror CLI logging** — `mirror:init`, `mirror:refresh`, and `mirror:verify` now call the new `initCliLogging()` before running, so their status/progress output — and the ingester's — is actually emitted instead of silently dropped by the framework logger's uninitialized-singleton guard ([#8](https://github.com/cyanheads/faa-aircraft-registry-mcp-server/issues/8)).

## Dependencies

- `tsc-alias` `^1.9.0` → `^1.9.1`
